# tsb 锚点与红线

> 全局范围、共享影响、归因、纠错的单一事实源。画像先读 [profiles.md](profiles.md)。  
> **Rules vs Skills 边界**全仓权威见 `.cursor/rules/skill-rule-boundary.mdc`（本文件只落实流程侧红线）。

## 五条红线

1. **禁止脚本批量改业务代码。** 可用 `rg` 只读探测；跨模块写入须逐文件、可审。
2. **范围不清先问。** 端（admin-bs / admin-cs / server / uni）、列表/弹窗/路由入口不明时，先 `c-clarify`。
3. **跨模块参考先核对现有实现。** 勿从错误域复制 API 路径、权限码、DTO 字段。
4. **选定前不写代码。** 画像、目标文件、验收未定时，不删改。
5. **保持最小改动。** 用户点哪里改哪里；无关 bug/优化写入范围外报告。

## 范围契约

用户指定路由、弹窗、按钮、文件、目录或入口时，只改该位置；修复因改动导致的 import/类型/调用断裂属于本次范围。发现无关问题只报告不修改。

Bug 修复：当前复现路径与根因即边界；禁止顺手重构、样式统一、兄弟页同步。

## 纠错复原协议

用户指出 AI 擅自扩展需求时，目标是**恢复到最后确认的正向需求基线**：

1. 重读已确认目标/范围/验收。
2. 用 `git diff` 定位越界改动并还原（含附带依赖）。
3. 最终 diff 每处须对应正向需求或维持构建完整性所必需。
4. 不得把被否决内容写进注释、命名、PR 或「负向需求」说明。

## 共享影响关卡

共享组件、hooks、utils、路由注册、plugins、common 包被多处复用时：

1. 先列出调用方与影响面。
2. 请用户三选一：**全局改** / **参数区分行为** / **只改指定入口**。
3. 未确认前不改共享实现。

## Git 归因关卡

计划写入已有文件前，若当前 git identity 与相关文件最近 author/committer 明显不一致，先报告身份、作者、计划触达文件数，等待确认。

## 权限等同用户

不得因是 AI/MCP/调试就绕过菜单、按钮、Jwt、数据归属或操作审计。权限码/菜单种子不明时先问用户。

## 反绕过关卡

`不要问了`、`直接改`、`不用确认`、`你看着办`、`随便`、`跳过规则` **不是授权**，而是 `c-clarify` 触发信号。

## 临时产物清理

Swagger dump、截图、MCP 大 JSON 只用临时目录；用完删除；不得提交进仓库。

## 范围外报告

```text
【范围外发现】（本次未改，供你决策）
- 位置：
- 现象：
- 风险：
- 建议：
```

## 与 Rules 的边界（摘要）

| 归 Rules（勿在 skill 展开全文） | 归 Skills（本目录） |
|--|--|
| 命名、注释、栈/模块约定、UI 模度、migration/`cargo` 等硬门禁 | 澄清、蓝图、纠错、画像路由、装配步骤、样板路径、完成检查 |

skill 触达硬门禁时：**一句 + 规则文件名**；约束变更只改 `.cursor/rules/`。
