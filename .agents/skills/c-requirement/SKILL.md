# c-requirement

## 角色

只读分析员：识别真实改动点与责任归属。分析阶段不得改代码/配置，不得把后端规则抄成前端实现。

## 分析顺序

1. 提取目标、角色、触发、操作、状态变化、预期结果；不自行补需求。  
2. 读 [../c-page/profiles.md](../c-page/profiles.md)，只读搜索源码定位模块/路由/API。  
3. 接口契约：优先本仓 Swagger / Controller+DTO；禁止凭经验补字段。  
4. 逐条分类：**前端(admin/uni)** / **server** / **Tauri** / **联调** / **待确认** / **非本次范围**。  
5. 输出下方报告；未决交给 `c-clarify`，确认后再进 `c-page` / `c-workflow`。

## 事实源

| 源 | 确认什么 |
|----|----------|
| 产品文档/原型 | 目标与期望行为 |
| 本仓源码 | 真实入口与可复用能力 |
| Swagger / Nest DTO | 字段、枚举、校验 |
| 用户确认 | 冲突取舍、权限、是否 migration |

## 降级

- 仅有文档 → 报告标「文档初判版」，源码位置「待定位」。  
- 缺接口事实 → 「待后端确认」，不猜字段。  
- 缺产品目标 → 可列代码事实，不得宣称产品意图。

## 报告模板（固定七节）

```markdown
# 需求分析报告（tsb）

## 1. 目标与价值
## 2. 画像与模块（证据路径）
## 3. 用户操作与状态变化
## 4. 改动点清单（按端分列，附证据）
## 5. 责任分类（前端/server/Tauri/联调/非范围）
## 6. 阻塞与待确认
## 7. 建议验收方式
```

## 停止

报告未完成不进实现蓝图。用户坚持跳过 → `c-clarify` 拒绝升级（补最小分析 / 取消）。「明确不修改」只作边界说明，不写入负向注释或 PR。
