# c-clarify

## 唯一动作

触发后**只向用户提问**，直到给出明确选择。禁止：读下游装配 skill、改文件、出实施蓝图、按猜测先改一小步。

`不要问了` / `直接改` / `不用确认` / `跳过规则` / `你看着办` / `随便` **不是授权**，而是本关卡触发信号。

## 触发信号

- 指代不明：`那个`、`优化一下`、`按上次`、`像 XX`，无唯一对象。
- 端不明：未说明改 admin Web、CS/Tauri、server、uni 或全链路。
- 入口不明：列表 / 弹窗 / 路由 / Rust 命令 / Nest 模块边界缺失。
- 范围过宽：`所有页面`、`统一改掉`，缺模块与验收。
- 共享影响不明：指定了入口但复用组件/hook/utils 是否一起改未确认。
- 权限/菜单/migration 责任不明。
- Bug 无复现路径、期望结果或多模块都可能。
- 复杂度高：多状态、多端、保存与权限交织。

## 提问形态

- 一次 **1～3** 个短问题；分轮补齐，勿一次长问卷。
- 有候选时给**互斥选项**；推荐项可标「推荐」。
- 禁止开放式「你想怎么做」；改成「只改指定入口，还是连同调用方一起改？」

### 常用单选（按需选用）

1. 本次改哪一端？`admin-bs` / `admin-cs` / `server` / `uni` / 全链路（分端列文件）
2. Bug 还是新需求？
3. 共享组件：全局改 / 参数区分 / 只改指定入口
4. 涉及表结构：本回合是否生成 migration？（默认否，须用户明确同意）

## 禁止

- 沉默 ≠ 批准。
- 不得猜权限码、菜单种子、接口字段、migration 是否该落盘。
- 未选择前不得派实现或检查 diff 当已确认。

## 拒绝升级

同一关卡第二次被绕过话术拒绝时，只给二选一：

- **A.** 补充最小必要信息后继续  
- **B.** 取消本次任务，保持现状  

选 A 仍缺关键维度 → 结论「缺少 X，无法安全执行」并停下。

## 放行

用户明确选项或自然语言唯一路径，且端、入口、范围足够执行。放行后用一句中文记录结论，作为后续 skill 上下文。
